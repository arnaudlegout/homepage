Python data science training — level 2

Polars, Numba, Multiprocessing: advanced data manipulation

⏱ 3 days 👥 ≤ 10 people 📍 On site or remote 🌐 English or French 🎯 Advanced 👤 Pandas users in production 🏢 In-company ★ 4.93/5

Pandas is essential in Python data science — but its limits show up quickly: excessive memory use, single-threaded execution, a sometimes inconsistent API. This course gives your teams the tools to go beyond these limits.

Polars redefines data manipulation in Python: an engine written in Rust, native parallelism, lazy evaluation, and the ability to process datasets larger than the available RAM thanks to its streaming engine. It is today the best choice to take a data pipeline from prototype to production.

I use Polars every day in my own research, in particular to analyze the entire Bitcoin transaction graph — 16.5 billion links between 1.5 billion addresses, stored in partitioned Parquet files. This course is built on that practice: what I wish I had known when my Pandas jobs took weeks and saturated the RAM — and moving to Polars brought them down to a few hours.

After this course, your staff will be able to

  • Write or rewrite their data processing in Polars for significant speed gains
  • Process datasets larger than the available RAM with the Polars streaming engine
  • Read and write Parquet files with Polars and PyArrow for efficient storage and exchange
  • Speed up their numerical computations with Numba and JIT compilation
  • Parallelize independent CPU-bound tasks with the multiprocessing module
  • Choose the right performance strategy for the context: Polars, Numba or multiprocessing
  • Apply best practices for high-performance data manipulation

Detailed program

Module 1 — Polars, the modern replacement for Pandas

Polars architecture: Rust engine, native parallelism, Apache Arrow. The core API: Series, DataFrame, essential operations. Lazy evaluation and query optimization. The streaming engine: processing data larger than RAM. Polars expressions: the most powerful API for data manipulation. Handling missing data. Aggregations and windows: group_by, over. Joins and concatenations. Reshaping: pivot and unpivot. Time series: resampling, rolling windows, time zone handling. The Parquet format: reading/writing, compression, partitioning, interoperability with PyArrow and Pandas. Migrating from Pandas to Polars: strategies and equivalences. Comparative benchmark on real cases.

Module 2 — Numba, JIT acceleration for numerical computing

The principle of JIT compilation with Numba. The @jit decorator: when and how to use it. Speeding up loops and NumPy functions. Parallelization with @jit(parallel=True) and prange. Use cases: numerical simulation, signal processing, scientific computing. Numba's limits and best practices.

Module 3 — Multiprocessing, multi-process parallelism in Python

The Python GIL and its implications for CPU-bound parallelism. Python without the GIL (the free-threaded build, officially supported since Python 3.14): what changes, and why multiprocessing remains the standard solution today. The multiprocessing module: Process, Pool, Queue, Pipe. Pool.map() and Pool.starmap(): parallelizing independent tasks. Process start methods (fork, spawn, forkserver, the default on Linux since Python 3.14) and their consequences for existing code. Memory sharing and inter-process communication. multiprocessing vs Numba vs Polars: when to use which. Common pitfalls and debugging multiprocessing code.

Frequently asked questions

Does Polars completely replace Pandas?

Polars is today the best choice to take a data pipeline from prototype to production. The course covers migrating from Pandas to Polars, with strategies and equivalences. In practice, many teams keep both during a transition period — the course prepares them to manage this coexistence.

What is the Polars streaming engine and when do you need it?

The Polars streaming engine processes datasets larger than the available RAM by transparently handling the data in chunks. It is covered in module 1. A typical case: a 200 GB Parquet file on a machine with 32 GB of RAM.

What is the difference between Numba and multiprocessing, and when should you choose one or the other?

Numba speeds up intensive numerical computations through JIT compilation — useful for loops or NumPy functions. Multiprocessing parallelizes independent tasks by working around the Python GIL — useful for "map"-style CPU-bound processing. Module 3 explicitly covers the comparison and the selection criteria.

Do I need to take the level 1 course first?

The level 2 course assumes an intermediate command of Python and practice with Pandas/NumPy. The Python data science level 1 course is the natural way in, but an equivalent level acquired through practice is also fine.

Is this course suitable for researchers who process large volumes of data?

Yes, this is precisely the target audience. I use Polars every day in my own research, in particular to analyze 16.5 billion Bitcoin transactions stored in partitioned Parquet files — the course is built on this real practice.
